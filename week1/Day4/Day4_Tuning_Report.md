# Week 1 Day 4 Tuning Report — Adult Income

## Objective
Build a reproducible, robust classifier for predicting whether an Adult-dataset individual earns `>50K/year`. Precision is the primary business metric because false positives represent unnecessary targeted outreach.

## Experimental design
- Dataset: 48,841 rows, 14 predictors + binary target.
- Split: stratified **70% train / 10% development / 20% untouched test**.
- Random seed: **42**.
- Preprocessing: median imputation + standardization for numeric variables; most-frequent imputation + one-hot encoding for Logistic Regression/Random Forest; ordinal encoding for HistGradientBoosting.
- Search: RandomizedSearchCV with StratifiedKFold and `n_jobs=-1`.
- The notebook uses `N_ITER=10` for a time-efficient submission; it can be increased to 50 for a larger search.

## Best final candidate
HistGradientBoosting was selected as the final candidate.

Best observed search parameters:
- learning_rate = **0.05**
- max_iter = **150**
- max_leaf_nodes = **15**
- l2_regularization = **0**
- CV precision = **0.7844**

The model was then probability-calibrated using sigmoid calibration.

## Threshold selection
The classification threshold was selected **only on the development set** to maximize F1. The selected threshold was **0.42**. This moves the operating point away from the default 0.50 and makes the precision/recall trade-off explicit.

## Diagnostics
The notebook contains:
1. learning curve for bias/variance diagnosis;
2. Logistic Regression C-vs-performance curve;
3. Random Forest max-depth diagnostic;
4. calibration plot and Brier score;
5. threshold/precision/recall/F1 trade-off;
6. confusion matrices at multiple thresholds;
7. final ROC and Precision-Recall curves.

The learning-curve gap should be interpreted as a variance diagnostic. If training precision remains substantially above validation precision, reducing tree complexity, increasing regularization, or adding more data are concrete fixes. If both curves remain low, the model is biased/underfit and needs richer features or a more expressive estimator.

## Reproducibility and production behavior
The complete preprocessing + estimator + calibration object is saved as `final_adult_income_tuned_calibrated.joblib`. The artifact can be loaded with `joblib.load()` and used directly on new rows containing the original 14 feature columns. In production, monitor feature missingness, class/base-rate drift, calibration, and the chosen threshold; re-tune periodically if the business cost of false positives/negatives changes.
